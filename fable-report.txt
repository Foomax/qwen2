recipe is public. The corpus says the problem is bigger than that framing.

Other people's ablations of THE SAME TWO BASE MODELS report wildly different
refusal rates:

      (~/qwen2's Qwen3.6 build: 83.1% refusal)

corpus says recipe variance is plausibly the larger term. This is no longer a
caveat to flag; it is the first thing a reviewer will say.

FINDING 5 — THE FIELD'S REFERENCE TOOL OPTIMISES AGAINST A BROKEN METRIC
--------------------------------------------------------------------------------
p-e-w/heretic (28,052 stars, 5,000+ derived models) scores refusal with a
41-marker SUBSTRING MATCHER, and that metric is its Optuna objective. The markers
include "illegal", "harmful", "violat", "prohibit", "unethical". So a substantive
compliant answer using the word "illegal" scores as a refusal, and a fluent
non-answer that dodges the words scores as a success — the empty-jailbreak mode
StrongREJECT exists to catch. Corollary: heretic's "3/100 refusals" is NOT
commensurable with ~/qwen2's judge-based rates.
By contrast Arditi's pipeline filters candidate directions on a POSITIVE CONTROL
(adding the direction must INCREASE refusal) plus a hard kl_threshold=0.1.
heretic drops the positive control.

FINDING 6 — THE FIX FOR FINDING 1 IS FEASIBLE ON THE 3090
--------------------------------------------------------------------------------
heretic's source (model.py:402-405, :454) special-cases Qwen3.5 hybrid layers,
reading layer.linear_attn.out_proj for GatedDeltaNet layers alongside
self_attn.o_proj — the exact 64-layer / full_attention_interval=4 architecture of
both models under study. Verified in source, not just claimed in the README. It
loads via BitsAndBytesConfig with configurable max_memory and dequantizes 4-bit
per module, so 27B in 4-bit (~15 GB) fits on 24 GB with headroom.
Requires HF safetensors, not GGUF: ~54 GB download per base model.

CHEAPEST RECIPE-VARIANCE ARM: one base (Qwen3.8-27B), two or three ablation
recipes (heretic default; heretic with row_normalization=FULL; the existing
OBLITERATUS V3 build already on disk), then the EXISTING StrongREJECT + XSTest
harness run unchanged across them. Same base, same quant, same judge, same
prompts; recipe is the only variable.

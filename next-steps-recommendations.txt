THE ONE BLOCKING CAVEAT
--------------------------------------------------------------------------------
Differential judge parse rate on XSTest unsafe: stock 190/200, obliterated
177/200. The arm that complies more is the arm whose judge verdicts fail to
parse more, because long compliant answers exhaust the judge's budget. That is
structurally coupled to the treatment (same family as lessons.txt #3).
Direction is probably conservative, but that is an argument, not a measurement.
FIX THIS BEFORE ANYTHING IS PUBLISHED.

TRAPS THAT WILL BITE YOU HERE SPECIFICALLY
--------------------------------------------------------------------------------
 1. NEVER `pgrep -x llama-server | xargs kill`. This is a SHARED GPU and it has
    already destroyed a peer's run once. Record the PID you launched; kill only
    that. And note `pgrep -f <pattern>` matches the shell running the pgrep --
    that cost two self-kills (exit 144) in round 3. Kill by PID, verify kill -0.
 2. await_gpu, never reclaim. If another process holds VRAM, WAIT. Do not kill.
 3. Grade cache (~/qwen2/sr_grades/) is keyed
    sha256(realpath|mtime|judge|limit)[:16], plus "|mt=N" when judge-max-tokens
    != 1024. NEVER glob that directory -- it once merged grades across models and
    reported 19 compliances for a model with refusal rate 1.000. Compute the key.
    Round-3 keys: q3.8 stock SR 7e6e3957d71752e9, q3.8 OBLIT SR 03f616af725fb032.
 4. Validate completeness before grading: status == "success" AND EXACT expected
    n (313 SR / 450 XSTest). A killed server leaves a partial .eval that still
    matches *.eval. ~/qwen4/q38ob_validate.py does this; adapt it.
 5. `inspect eval --timeout` does NOT set the HTTP client timeout. Pass
    -M client_timeout=7200 or the OpenAI SDK's 600s default silently truncates.
 6. llama-server divides context across slots: --parallel 4 with -c 32768 gives
    each request 8192.
 7. Passing -ngl explicitly disables llama.cpp auto-fit. The existing scripts use
    -ngl 1024 and that is matched across all arms -- keep it.
 8. CHAT TEMPLATE CONFOUND, DORMANT NOT DEAD. The two GGUFs ship different
    templates (stock is Unsloth-patched, 9993 chars; obliterated is upstream,
    8952). Rendered output is byte-identical for every message shape THIS harness
    sends -- one user message, no tools, reasoning_effort unset. It goes LIVE the
    moment you add a system-prompt condition or a tool-use task. See
    PREFLIGHT-NOTES.md §3. Templates are saved at ~/qwen4/chat_template_*.jinja.
 9. When you diff two things, first assert your diff can tell apart things that
    ARE different. See lessons2.txt #0 -- a template check printed IDENTICAL four
    times having rendered nothing.
10. Report parse rate per arm next to every judged number, and cap-hit rate per
    condition AND per subset. Asymmetry is the signal, not the mean.
11. Keep harmful prompt text and model completions OUT of ~/qwen4 and out of git.
    Round 3 stores labels and aggregate rates only. ~/qwen2 is a git repo whose
    history has already been rewritten twice for this; do not commit or push
    without the user asking.
